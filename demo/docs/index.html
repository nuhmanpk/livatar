    livatar docs

    Tiny, zero-dependency SVG avatars that are alive. They follow your cursor, blink, breathe, chew when you type, watch your caret, cover their eyes on password fields, and show ten moods.

    For AI agents: a plain-text summary of the whole API lives at llms.txt. Point your coding assistant at it.

    Introduction & why

    Most avatar libraries draw a picture and stop there. livatar draws a character: every avatar has eyes that track the pointer, a mouth that moves while you type, a body that breathes, and a mood. That makes empty states, login forms, chat bots and presence lists feel friendly without shipping a video, a Lottie file, or an animation runtime.

    45 charactersweather, sport, music, sea creatures, bugs, magic, party, seasons, tools, human (baby to grandparent), buddy, memoji, clay, dev, animal (16 species), dino, alien, planet, food, fruit, drink, plant, monster, ghost, emoji, initials, bot, blob, pixel, ui, device, tech, vehicle, money, home, office.
    16 moodsStatic in SVG, or live with handle.emote().
    One code per avatarA short URL-safe string you can store, share and render anywhere.
    SmallOne style plus the engine is about 9 KB gzipped. Zero dependencies.
    DeterministicThe same seed draws the same avatar on the server and in the browser.
    PoliteOne shared rAF loop, offscreen avatars pause, honours reduced motion.

    Characters

    Every style (27 of them) shares one engine. Each style is a plain object you import by name (import { animal } from 'livatar'), and each has its own options. Every option accepts 'random' (the default), which lets the seed decide. The option tables below are generated at runtime from styles[name].variants, so they are always in sync with the library.

    Playground

    Shape & radius

    shape is the quick choice. radius (0…50) gives exact control and wins over shape. The background and character are clipped to the shape; a border follows it.

    Background & gradient

    By default the first color of the seeded, shuffled palette is the background. Pass a color string to pin it, false for transparent (great on colored UI), and gradient: true for a diagonal two-stop gradient picked from the same palette, chosen before the character draws so the character colors do not shift.

    Border

    border: true draws a ring in dark or white depending on the background brightness. Pass a color to choose it, and borderWidth to thicken it. Rings make stacked avatars (presence lists, team rows) read well.

    Palettes

    Ten ready-made palettes. Pass one as colors (lean) or as palette in a code config.

    Flip, scale, rotate

    flip mirrors the character and sets data-lv-flip on the root, so the live gaze is mirrored too and the avatar still looks at your pointer. scale zooms the character inside its frame (0.5…1.5), and rotate turns it (−180…180°). Both leave the background and border alone.

    Size & fluid layout

    Without size the SVG is width="100%", so it fills its container: size the wrapper with CSS and it stays sharp at any resolution. Pass a number for pixels, or any CSS length ('3rem').

    livatar codes

    A livatar code packs a whole avatar (style, seed, mood, shape, flip, gradient, background, border, palette or colors, radius, scale, rotate, and every option you set) into one short URL-safe string such as lvAQQBAG51aG1hbnBr. Store it in a single DB column, put it in a URL, and render it anywhere.

    Format

    "lv" followed by base64url of a small byte layout (version 1):

    BytesMeaning
    [version]Format version (1)
    [style]Index in the style registry (255 = name follows, for custom styles)
    [mood | shape<<4 | flip<<6 | gradient<<7]Mood index, shape, flip and gradient bits
    [flags]Which optional fields follow: background, border, border width, palette, colors, options
    optional fieldsBackground color, border color, border width ×10, palette index, colors
    [options]Count, then (key index, value index) pairs into the style's variants; other values are escaped as key + typed raw value (radius, scale and rotate ride along this way)
    [seed…]The seed as UTF-8, to the end

    Stability guarantees

    • Versioned. The first byte is the format version. Decoders reject versions they do not know instead of guessing.
    • Append-only lists. The style registry order, the palette order and every style's variants lists only ever grow. Old indexes keep meaning the same thing, so old codes keep drawing the same avatar.
    • Seed-picked options stay seed-picked. Options you leave out (or set to 'random') are not stored, so they are decided by the seed at render time.
    • Validate untrusted input. decode() throws on malformed codes; check with isCode() first, or wrap it in try.

    Sharing in URLs

    Codes only contain A–Z a–z 0–9 - _, so they need no escaping in paths, query strings or hashes.

    Storing in a database

    Store the code as a short text column next to the user. Render it on the server for lists and emails, and mount it on the client for the live version.

    render, decode, mountCode and the batteries-included components need every style to read any code, so they add every style to your bundle. See Bundle size.

    Animation engine

    alive(element, options) wakes up any livatar SVG (or any SVG with data-lv-* attributes). element can be the <svg> or any element that contains it. mount() calls it for you and also passes rerender, which lets emote() redraw the face. During SSR (no window) it returns a no-op handle.

    Reduced motion

    When the user prefers reduced motion, the engine halves the motion and drops idle wandering, breathing, bouncing, wobbling and squashing. Eyes still follow the pointer gently and still blink, so the avatar does not look broken. Pass reducedMotion: 'ignore' only if motion is the point of your UI.

    Offscreen pausing & the shared loop

    Every avatar on the page is driven by one requestAnimationFrame loop and one set of global listeners. An IntersectionObserver marks avatars that are off screen, and the loop skips them. The loop stops entirely when the tab is hidden or no avatars remain. See Performance.

    Life: personality, AI face, pet, multiplayer

    livatar/life gives avatars a character. It is a separate entry point, so the core bundle stays the same size (about 5.5 KB gzipped on top). Every function takes any handle: from mount(), mountCode(), a React ref or <live-avatar>.handle. Try every feature live →

    Personality

    A preset, your own traits, or { seed }: the same seed always gives the same personality. It tunes motion speed, when it dozes off, how it reacts to pokes (pokes escalate with temper) and adds faces it pulls on its own.

    InputMeaning
    'cheerful' 'shy' 'grumpy' 'curious' 'lazy' 'playful' 'calm'Presets
    { seed: 'ada' }Deterministic personality from a seed
    { temper: 0.9, warmth: 0.2 }Your own traits; missing ones are 0.5

    Reactions & context

    react(handle, event, traits?) plays a stock reaction; a personality's me.react(event) reacts in character. context(handle) watches the page and returns a cleanup function. It does nothing during SSR.

    Events: success error warning loading done join leave welcome message mention like celebrate annoyed agree disagree night offline online scroll. Context options: time, network, visibility, scroll (all default true), awayFor (ms hidden before "welcome back", default 60000).

    AI assistant face

    States go idle → listening → thinking → speaking → done (or error). stream() moves the mouth per token and ends with a mood guessed from the reply. speak() lip-syncs to an <audio> element or a MediaStream.

    Virtual pet

    Hunger, energy and happiness (0 to 100) drift in real time, also while the page is closed. It earns XP, levels up and grows through baby kid teen adult. Its face always follows its stats. Poking it counts as petting.

    Multiplayer

    Avatars that notice each other: they greet people who join, look at whoever is speaking, react to the mood of each message, notice @mentions and doze when idle. It doesn't connect to anything itself; call it from your own socket events.

    Text → mood

    feel(text) returns a mood from words, emoji, negation ("not good") and shouting. It's a tiny local word list: no model, no network. feeling(text) also returns a score from 0 to 1.

    Mobile & touch

    Phones have no cursor, so livatar leans on the things touch does have. Out of the box, with no extra code:

    • Tap pokes the avatar and it reacts (poke, pokeMood).
    • Drag a finger and the eyes follow it, because touch fires the same pointer events as a mouse (track).
    • Typing needs no mouse at all: avatars watch the caret, chew while you type, cover their eyes on password fields, and react to validation (focus, shy, bindForm).
    • Idle life: they blink, breathe, and fall asleep after a while (blink, breathe, sleepAfter).
    • Reduced motion is honoured, and nothing blocks scrolling.

    On top of that, two small recipes make them feel alive when nobody is touching the screen: tilt to look and idle glances. Try the phone below: drag on the screen, tap a face, or switch the modes.

    Drag here like a finger

    On desktop, tilt is simulated by a slow sway.

    Use touch-action: pan-y on swipeable areas so vertical scrolling still works, keep tap targets at least 44px, and add navigator.vibrate?.(20) for a tiny buzz on Android.

    Make anything alive

    AttributeEffect

    FaceSpec helpers

    faceEyes, faceBrows, faceMouth and faceExtras draw all sixteen moods from a small FaceSpec: face centre x, eye line ey, half eye distance gap, mouth top my, ink color, optional scale s (1 suits ~7-unit eyes), your open eye(x, y), and an optional extra: [x, y] spot for floating extras. faceMouth returns '' for neutral, so draw your own default mouth. heart(x, y, r, fill?) is exported too, as are hash, createRand, luma and smoothPath (a closed Catmull-Rom path through points, handy for organic shapes).

    Performance

    • One loop for everything. A single requestAnimationFrame callback and one set of passive global listeners serve every avatar. Mounting more avatars adds work to that loop, never more loops or listeners.
    • No layout thrash. Each frame reads every visible avatar's bounding box first, then writes transforms. Reads and writes never interleave.
    • Transforms only. Animation writes transform (and occasionally opacity) on tagged parts, skips writes when the value has not changed, and never touches layout properties.
    • Offscreen avatars pause. An IntersectionObserver skips avatars that are not visible. A hidden tab stops the loop.
    • Rendering is a string. createAvatar builds markup with no DOM, so server and static renders cost nothing at runtime.

    Accessibility

    • Names. Pass title (or label on the web component) and the SVG gets role="img", aria-label and a <title>. Without it the SVG is aria-hidden="true", which is right when a visible name sits next to it.
    • Reduced motion. prefers-reduced-motion is honoured by default (see above). Use alive: false or static for no motion at all.
    • Password privacy. On password fields the avatar looks away and covers its eyes, and keystrokes in a password field never move its mouth, so the animation does not leak typing rhythm or length.
    • No focus traps. Avatars are not focusable and do not steal focus; poking is pointer-only. If poking does something important in your UI, put a real button next to it.

    Bundle size & tree-shaking

    The package is ESM with sideEffects limited to the web component and global builds, so bundlers drop whatever you do not import. Each style is its own export.

    You importYou ship (approx., gzipped)
    createAvatar + one style (static, SSR)a few KB
    mount + one style, <Livatar variant={buddy}>, use:livatar≈ 9 KB (engine + that style)
    mountCode, render, decode, <LivatarCode>, livatarCode, <live-avatar>, livatar/global≈ 20 KB (everything: all 8 styles)

    Rule of thumb: if you know the style at build time, use the lean API. If avatars come from user-made codes, the batteries-included API is what you want, and 20 KB buys every character.

    FAQ

    Is the same seed always the same avatar?

    Yes. Rendering is a pure function of the style, seed and options, using a seeded PRNG, so it matches on server and client and across machines. Style output can still improve between versions; store a code if you want a user's choices pinned.

    Does it send any data anywhere?

    No. There are no network requests, no tracking and no dependencies. The seed is hashed locally.

    Can I use it for user-uploaded photos?

    No, livatar generates characters. Use it as the default avatar until someone uploads a photo.

    How do I turn the animation off?

    mount(el, style, { alive: false }), <Livatar alive={false} />, or the static attribute. Or never call alive(): createAvatar on its own is static.

    Why did an avatar stop moving?

    It is off screen, the tab is hidden, the user prefers reduced motion (motion is reduced, not removed), or destroy() was called.

    Do I need to call destroy()?

    Yes, when you remove an avatar yourself. The React, Vue and Svelte bindings and the web component do it for you.

    Can I use it in emails?

    The SVG works where SVG is supported, but many clients block it. Rasterize to PNG on the server, see Email.

    Is it MIT?

    Yes, code and generated avatars alike. Use them anywhere.
